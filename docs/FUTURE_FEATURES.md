# Future Features

This is the unordered backlog of concrete package mechanisms that are not implemented current features. Desired end-to-end outcomes belong in `FUTURE_CAPABILITIES.md`; admitted work belongs in `CURRENT_TASK.md`.

## Variant And Overlay Mechanisms

- iOS/SwiftData variant manifest, project-specific owner routing, health commands, preservation fixtures, and retirement contract after a real project supplies admission evidence.
- Additional desktop, service, CLI, data, automation, and AI-project overlays backed by project-shaped fixtures.

## Distribution Mechanisms

- Owner-approved publication channel and guided install UX.
- Optional signed package and provenance metadata if distribution moves beyond local Git transfer.
- Versioned migration/recovery UX and authenticated package verification where the selected distribution model requires them.

## Evaluation Mechanisms

- Additional cold-start comprehension or recovery evaluation harnesses only when they add evidence beyond the deterministic installed-owner audit.
- Privacy-safe, repeatable fresh-session evaluation records with explicit model/human and environment boundaries.

## Shelved Workflow Controller

- Deterministic single-Action selection from durable Execution State.
- Machine-checkable task packets, write authorization, verification, return, recovery, and stop contracts.
- Closed-by-default GitHub, remote-agent, local-machine, and ATLAS provider adapters.
- Lease expiry, abandoned-writer recovery, source-changed-after-test rejection, and conflicting-return handling.

The Controller is explicitly not implemented by the current continuity workflow.

Future mechanisms do not become enabled modules, supported capabilities, or live work merely by appearing here.
