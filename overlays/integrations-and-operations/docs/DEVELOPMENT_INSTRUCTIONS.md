# Development Instructions

Purpose: practical default rules for project work before a project-type-specific kit is installed.

## General Rules

- Build the real working slice, not just a placeholder.
- Prefer existing patterns and structure before adding new abstractions.
- Keep behavior deterministic where practical.
- Make failure behavior explicit.
- Make logs intentional, not accidental debug spill.

## Implementation Expectations

- Define the owning layer before editing.
- Keep changes scoped to the requested outcome.
- Add or update tests when practical.
- Keep documentation aligned with real behavior.

- Test: `[COMMAND]`
- Build: `[COMMAND]`
